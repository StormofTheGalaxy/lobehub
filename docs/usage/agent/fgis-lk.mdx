# ФГИС ЛК: отчётность лесопользователя

Инструмент готовит файл `.xml` «Отчёта о воспроизводстве лесов и лесоразведении»
(форма 1-ВЛ) — тот самый файл, который загружается во ФГИС ЛК. Портал и 1С для
этого не нужны: формат отчёта государственный, схемы и справочники Рослесхоз
публикует открыто.

<Callout type="warning">
  Это официальная отчётность. Инструмент проверяет форму документа, но не знает,
  что происходило в лесу. Перед подписанием обязательна ручная сверка — чек-лист
  выводится после каждой успешной сборки.
</Callout>

## Что нужно один раз перед началом

1. **Установить навык.** Магазин навыков → «ФГИС ЛК: отчётность» → установить,
   затем включить его для нужного агента. По умолчанию навык не установлен:
   он отраслевой и не нужен большинству агентов.
2. **Проверить, что на сервере есть `xmllint`.** Это внешняя проверка документа
   по официальной XSD-схеме. В macOS он входит в систему, в Linux ставится
   командой `apt-get install libxml2-utils`. Если его нет, инструмент не будет
   записывать файл и прямо скажет, что документ нельзя считать проверенным.
3. **Убедиться, что версия схемы актуальна.** Спросите агента: «какая версия
   схемы используется?» — он вызовет `describeEnvironment`. В комплекте
   поставляется `forestReproduction 3.0.7`, действующая с 05.05.2026.

## Развёртывание

Инструмент выполняется на сервере и требует двух вещей: бинарника `xmllint` и
каталога с официальными схемами. Что это значит для разных способов запуска:

Всё необходимое уже входит в образ, который собирает наш CI
(`ghcr.io/stormofthegalaxy/lobehub`): `xmllint` с его библиотеками, официальные
схемы в `/app/fgislk-data` и переменная `FGISLK_DATA_DIR`, указывающая на них.
Отдельно настраивать ничего не нужно.

| Способ запуска | Работает | Примечание |
| --- | --- | --- |
| `docker-compose/deploy`, `production` | да | тянут наш образ из ghcr.io |
| Свой образ из этого репозитория | да | `docker build -t our/lobehub .` |
| `docker-compose/dev` + `pnpm dev` | да | в macOS `xmllint` встроен, в Linux — `apt-get install libxml2-utils` |
| Апстримный образ `lobehub/lobehub` | нет | это сборка проекта LobeHub, нашего кода в ней нет |
| Vercel | нет | в serverless-окружении нет `xmllint` |

Образ приложения задаётся переменной `LOBE_IMAGE` и по умолчанию указывает на
нашу сборку. Чтобы взять апстримную (без этого инструмента), переопределите её.

Сборка образа проверяет себя сама: если `xmllint` не запускается или схем нет на
месте, шаг падает и образ не попадает в реестр. Это дешевле, чем узнать о
неработающем инструменте от пользователя.

### Обновление схемы без пересборки образа

Когда Рослесхоз выпустит новую версию схемы, не обязательно пересобирать образ —
достаточно смонтировать каталог томом:

```yaml
services:
  lobe:
    volumes:
      - ./fgislk-data:/opt/fgislk-data:ro
    environment:
      - 'FGISLK_DATA_DIR=/opt/fgislk-data'
```

Внутри каталога должны быть подкаталоги `schemas/` и `nsi/` того же вида, что и
в поставке.

## Как подготовить отчёт

Разговором. Приведите исходные данные — агент разложит их по форме и соберёт
файл. Примерный первый запрос:

```text
Подготовь отчёт о воспроизводстве лесов за 9 месяцев 2025 года.
Организация — ООО «Пример», ОГРН …, ИНН …
Лесничество Мухенское, участковое Сийское, квартал 19, выдел 17.
Лесоразведение лиственницей даурской, 0,0228 га, май 2025.
Документ-основание — договор № 321 от 09.04.2024, номер в ГЛР 00:00:0000000-00.0.
Вложения лежат в /data/otchet/files.
```

Дальше агент:

1. найдёт коды по официальным справочникам и покажет их вам парами
   «код — наименование»;
2. покажет, какие строки формы получатся: код строки, номер пункта, единица
   измерения, сноски;
3. соберёт XML и проверит его;
4. выведет вердикт и чек-лист ручной проверки.

Файл появляется на диске **только если он прошёл проверку по XSD**. Сборка идёт
во временный файл, и невалидный документ до целевого пути не доходит.

### Что нужно указывать точно

- **Учётные номера ГЛР** — лесничество, участковое лесничество, квартал, выдел.
  Они вложены иерархически: `27:19` → `27:19:4` → `27:19:4:19` → `27:19:4:19:17`.
  Источник истины — выписка из ГЛР, а не память.
- **Мероприятие** — наименованием из формы, кодом строки или номером пункта.
  Код строки и единицу измерения подставит инструмент, их вводить не нужно.
- **Площадь** — до 4 знаков после запятой; масса и количество — до 1 знака
  (сноска <3> формы).

### Чего делать не нужно

- Просить агента «написать XML» — он не должен и не будет писать разметку сам.
- Диктовать коды по памяти. Если код не найден точно, инструмент покажет
  похожие значения, но выбрать из них должен человек: «Дерево обыкновенное»
  является частью названия «Земляничное дерево обыкновенное (крупноплодное)»,
  и автоматический выбор увёл бы в отчёт другую породу.

## Проверка чужого файла

Отчёт, выгруженный с портала или сделанный в прошлом периоде, можно проверить
без пересборки: «проверь файл /data/otchet/forestReproduction.xml, вложения
в /data/otchet/files». Инструмент выполнит валидацию по XSD и смысловые
проверки.

Если файл сделан по устаревшей схеме, попросите перевести его на действующую:
часто достаточно замены пространств имён, структура документа не меняется.

## Что проверяется автоматически

| Уровень | Что именно |
| --- | --- |
| XSD | состав и порядок элементов, типы, принадлежность значений справочникам |
| Форма | код строки и единица измерения по приказу № 112, знаки после запятой |
| Арифметика | «в том числе» не больше «всего», сумма подчинённых строк не больше родительской |
| ГЛР | вложенность учётных номеров, принадлежность лесничества субъекту |
| Вложения | контрольные суммы MD5, ссылки фотофиксации, JPEG не менее 5 Мпикс, не более 12 точек |
| Даты | границы отчётного периода, год выполнения работ |

Находки делятся на три уровня: **ОШИБКА** — подавать нельзя; **ПРЕДУПРЕЖДЕНИЕ** —
посмотреть глазами; **СПРАВОЧНО** — к сведению. Документ считается готовым,
только если он валиден и ошибок нет.

## Что остаётся человеку

Инструмент не может проверить фактическую сторону отчёта. Перед подписанием
проверьте сами:

- учётные номера лесничества, квартала и выдела совпадают с выпиской из ГЛР;
- документ-основание есть во ФГИС ЛК и принадлежит вашей организации,
  номер и дата совпадают с записью в реестре;
- отчётный период и объёмы соответствуют фактически выполненным работам;
- реквизиты подписанта и доверенности действительны на дату подписания;
- приложены все документы, на которые ссылаются примечания.

**Подпись ставит человек.** Отчёт подписывается усиленной квалифицированной
подписью по ГОСТ — через КриптоПро, Госключ или портал. Агент этого не делает.
Подпись открепленная: после подписания файл нельзя пересохранять и
переформатировать, иначе она станет недействительной.
